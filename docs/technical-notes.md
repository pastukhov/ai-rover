# Технические заметки AI Rover

Этот документ для взрослого помощника и для будущих занятий в кружке робототехники. Он объясняет, как устроен ровер, как его прошивать, где искать проблемы и какие части проекта можно развивать.

## Текущая версия

Актуальная ветка проекта:

```text
master
```

Ключевое состояние прошивки:

- Wi-Fi и LLM настраиваются через веб-интерфейс.
- `include/secrets.h` больше не используется.
- Если STA-подключение к Wi-Fi не удалось, поднимается открытая точка доступа.
- IP-адрес показывается на экране и в AP, и в STA-режиме.
- Камера и vision-инструменты удалены из текущей прошивки.

## Аппаратная схема

### Основные компоненты

| Компонент | Роль |
|---|---|
| M5StickC Plus | Основной контроллер на ESP32-PICO-D4 |
| RoverC Pro | Моторная база, gripper, STM32-контроллер |
| Mecanum wheels | Омнинаправленное движение |
| Gripper | Захват лёгких предметов |

M5StickC Plus вставлен в RoverC Pro и управляет базой по I2C.

### I2C

RoverC Pro использует I2C-адрес:

```text
0x38
```

Основные функции:

- запись скоростей четырёх моторов;
- управление сервоприводом захвата;
- остановка движения при ошибках и аварийных сценариях.

Подробности по регистрам есть в [roverc-pro.md](roverc-pro.md).

## Архитектура прошивки

Проект собран на:

- PlatformIO;
- ESP-IDF;
- C/C++;
- FreeRTOS.

Главные файлы:

| Файл | Назначение |
|---|---|
| `src/main_idf.cpp` | Основная логика прошивки |
| `src/logger_json.h` / `src/logger_json.cpp` | Структурные JSON-логи |
| `platformio.ini` | Конфигурация PlatformIO |
| `docs/` | Документация |

### Основные подсистемы

| Подсистема | Что делает |
|---|---|
| Wi-Fi manager | STA/AP fallback, события подключения |
| Web server | Главная страница, управление, настройки, чат |
| NVS settings | Хранение Wi-Fi и LLM-настроек |
| Display | Статус, IP, режим сети, состояние захвата |
| Rover control | Моторы, повороты, захват, emergency stop |
| AI/OpenRouter client | LLM-чат и tool calls, если API key настроен |
| Logger | JSON-логи в UART и syslog |

## Настройки в NVS

Прошивка хранит настройки в NVS, а не в заголовочном файле с секретами.

Сохраняемые поля:

| Поле | Назначение |
|---|---|
| `wifi_ssid` | SSID Wi-Fi-сети |
| `wifi_password` | Пароль Wi-Fi |
| `llm_endpoint` | OpenAI-compatible endpoint |
| `llm_api_key` | API key |
| `llm_model` | Имя модели |

Сброс выполняется из веб-интерфейса кнопкой **Reset settings**. После сброса прошивка возвращается к значениям по умолчанию и при необходимости поднимает AP.

## Сетевой сценарий

### При запуске

1. Прошивка загружает настройки из NVS.
2. Если Wi-Fi SSID задан, запускается STA-подключение.
3. Если SSID не задан или подключение не удалось, запускается AP fallback.
4. В AP-режиме создаётся открытая сеть `AI-Rover-XXXX`.
5. На экране отображается IP-адрес.
6. HTTP-сервер доступен на порту `80`.

### AP fallback

Точка доступа открытая, без пароля. Это удобно для подарочного устройства и первого запуска, но имеет очевидное ограничение безопасности: рядом находящийся человек может подключиться к роверу, пока он в AP-режиме.

Практическая рекомендация:

- использовать AP только для первичной настройки;
- после настройки домашнего Wi-Fi работать в STA-режиме;
- не оставлять ровера включённым в публичных местах.

### mDNS

Прошивка публикует HTTP-сервис через mDNS:

```text
http://ai-rover.local/
```

mDNS удобен, но не гарантирован во всех сетях. Самый надёжный источник адреса - экран устройства.

## Веб-сервер

HTTP-сервер регистрирует несколько endpoint-ов:

| Endpoint | Метод | Назначение |
|---|---|---|
| `/` | GET | Веб-интерфейс |
| `/move` | GET/POST | Команды движения |
| `/chat` | GET/POST | Отправка LLM-запроса |
| `/chat_result` | GET | Получение результата LLM-запроса |
| `/settings` | GET | Чтение настроек |
| `/settings` | POST | Сохранение настроек |
| `/settings/reset` | POST | Сброс настроек |
| `/wifi_scan` | GET | Сканирование Wi-Fi-сетей |

Веб-интерфейс построен как одна страница: управление ровером и настройки находятся рядом. Это сделано, чтобы при первом запуске не искать отдельную страницу конфигурации.

## LLM-интеграция

Прошивка использует OpenAI-compatible API через клиент OpenRouter.

Настраиваемые поля:

- endpoint;
- API key;
- model.

Модель по умолчанию:

```text
openai/gpt-4o-mini
```

Если API key не настроен, AI-клиент не создаётся, а чат в веб-интерфейсе скрыт. Это нормальное состояние для первого запуска без LLM.

LLM может вызывать ограниченный набор инструментов:

- движение;
- поворот;
- stop;
- открыть захват;
- закрыть захват;
- прочитать IMU.

Vision/camera tools в текущей прошивке отсутствуют.

## Безопасность движения

Важные принципы:

- **BtnB** - аварийная остановка.
- Веб-кнопка **STOP** отправляет немедленную остановку.
- После AI-ошибки прошивка останавливает моторы.
- Долгие действия должны периодически проверять аварийную остановку.

Для занятий с ребёнком лучше начинать с малых скоростей и коротких команд, особенно на столе.

## Сборка

Минимальная проверка:

```bash
pio run
```

В этом репозитории обычно используется локальная виртуальная среда:

```bash
PLATFORMIO_CORE_DIR=.pio-core ./.venv/bin/pio run
```

PlatformIO environment задан в `platformio.ini`.

Текущая платформа закреплена так, чтобы не переходить на ESP-IDF 6:

```ini
platform = espressif32@6.12.0
```

Эта версия PlatformIO использует ESP-IDF 5.x.

## Прошивка устройства

Подключите M5StickC Plus по USB и выполните:

```bash
pio run --target upload
```

Или через локальную среду:

```bash
PLATFORMIO_CORE_DIR=.pio-core ./.venv/bin/pio run --target upload
```

После прошивки устройство перезагрузится. Смотрите экран: там должен появиться режим сети и IP-адрес.

## Serial monitor

Для просмотра логов:

```bash
pio device monitor --baud 115200
```

Логи приложения должны идти через единый structured logger:

```cpp
rover_log(const rover_log_record_t *record)
```

Формат логов описан в [logging-conventions.md](logging-conventions.md).

## Диагностика

### Ровер не создаёт AP

Проверить:

1. Загружается ли прошивка.
2. Нет ли panic/reset в serial monitor.
3. Инициализируется ли Wi-Fi.
4. Есть ли на экране **AP MODE**.

### Wi-Fi scan failed

В текущей прошивке `/wifi_scan` должен возвращать JSON даже при ошибке. Если веб-интерфейс показывает `scan failed`, нужно смотреть serial monitor и событие `wifi_scan_failed`.

Типовые причины:

- Wi-Fi ещё переключается между режимами;
- слабое питание;
- внутренняя ошибка Wi-Fi stack;
- слишком быстрый повторный scan.

### Веб-интерфейс открывается, но чат скрыт

Это штатное поведение без LLM API key.

Проверить:

1. Открыть Settings.
2. Заполнить LLM API key.
3. Указать model.
4. При необходимости указать endpoint.
5. Сохранить настройки.

### Ровер подключился к Wi-Fi, но `ai-rover.local` не открывается

Использовать IP-адрес с экрана. mDNS может не работать в некоторых сетях, на некоторых телефонах или при изоляции клиентов на роутере.

### Ровер не едет

Проверить:

1. Питание RoverC Pro.
2. Заряд батареи.
3. I2C-связь с адресом `0x38`.
4. Нет ли активной аварийной остановки.
5. Не зависла ли веб-команда движения.

## Как развивать проект

### Простые улучшения

- добавить готовые миссии в веб-интерфейс;
- добавить режим "медленно/быстро";
- добавить журнал последних команд;
- добавить страницу с диагностикой питания и Wi-Fi.

### Инженерные улучшения

- вынести web UI из строк C++ в отдельный генератор или embedded asset;
- разделить `src/main_idf.cpp` на модули;
- добавить unit-тесты для парсинга команд и настроек;
- добавить bounded queue для сценариев движения;
- расширить display state machine.

### Робототехнические эксперименты

- датчик расстояния;
- движение по линии;
- измерение проскальзывания;
- калибровка поворотов;
- автоматический захват лёгкого объекта.

## Минимальный checklist перед передачей ребёнку

1. Прошивка собрана без ошибок.
2. Устройство включается.
3. На экране есть AP или Wi-Fi IP.
4. Веб-интерфейс открывается.
5. Команды движения работают.
6. STOP работает.
7. BtnB останавливает движение.
8. Захват открывается и закрывается.
9. Заряд достаточный для демонстрации.
10. Ровер не стоит рядом с краем стола.

После этого можно переходить от "проверки устройства" к экспериментам. Самая ценная часть подарка - не готовая игрушка, а возможность менять правила, проверять гипотезы и видеть результат на реальном роботе.
